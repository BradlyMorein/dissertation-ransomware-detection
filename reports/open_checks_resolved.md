## Finding 2 — sequence identifiers shared between partitions

verify_partitions.py tests whether a sequence_id appears in more than
one fold. That test is only meaningful if sequence_id is unique across
the whole dataset. This checks whether it is.

```
fold            rows   distinct id       min       max
train      1,468,760       146,876         0   146,875
val          314,680        31,468         0    31,467
test         314,700        31,470         0    31,469
```

```
every fold numbers its sequences from 0   : True
every fold's identifiers are contiguous   : True
val and test id sets are subsets of train : True
```

**The FAIL is an artefact of the check, not a property of the data.**

Each fold numbers its own sequences from zero upward. sequence_id
is unique within a fold and is reused across folds, so identifier
0 names a different sequence in each of the three partitions. The
overlap the check reports is a collision of numbering ranges, not
sequences appearing in more than one fold. The smaller folds'
ranges sit entirely inside the larger one, which is why every
identifier in val and test is reported as shared.

Sequence disjointness follows from flow disjointness instead.
Sequences are constructed inside each fold after the split, from
that fold's flows alone, so no sequence can span two folds.

### Corroboration from the row counts

If sequences were built inside each fold, each fold's sequence rows
should be its flow count rounded down to a whole number of windows.

